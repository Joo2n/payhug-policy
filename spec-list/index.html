02

서비스 개요

선정산이 무엇이고 누가 어떤 순서로 관여하는지.

1. 서비스 정의

PayHug는 소상공인 가맹점의 카드 매출 및 배달 플랫폼 매출을 기반으로 선정산을 제공하는 서비스다.

핵심 가치는 다음과 같다.

어제 발생한 매출을 오늘 미리 지급하여 가맹점의 현금흐름을 개선한다.

2. 주요 사용자

  • 가맹점주
  • 총판·파트너
  • PayHug 운영 담당자
  • 정산 담당자
  • 개발·기획 관리자

3. 주요 매출 채널

  • 카드 VAN 매출
  • 배달의민족
  • 요기요
  • 쿠팡이츠
  • 향후 온라인 PG 매출
  • 향후 다날 연계 매출 가능성

4. 주요 시스템 영역

가맹점 서비스

  • 선정산 메인
  • 일별 매출
  • 선정산 예정액
  • 지급 내역
  • 정산 상세
  • 환급·추가 지급
  • 차감·회수
  • 선정산 제외
  • 알림톡 연결 화면

운영 어드민

  • 매출 대사
  • 선정산 산정
  • 지급 관리
  • 바로이체
  • 미지급 관리
  • 환급 관리
  • 과지급·미회수 관리
  • 회수 관리
  • 수동 지급·수동 회수
  • 알림 발송 이력

5. 기본 정산 흐름

현재 파악된 기본 흐름은 다음과 같다.

  1. 카드사·배달앱 승인 및 매입 정보 수집
  2. 매일 오전 10시 기준 데이터 최종 업데이트
  3. 전일 매출을 기준으로 선정산 대상 금액 산정
  4. 플랫폼 수수료, 카드 수수료, PayHug 수수료, 이체수수료 차감
  5. 다음날 오전 11시 30분과 오후 6시, 가맹점별 하루 2회 지급 (주말·공휴일 포함 매일)
  6. 이후 발생한 취소·환불·추가 매입·환급·정정 금액 반영
  7. 부족 지급은 추가 지급 또는 바로이체
  8. 초과 지급은 차기 지급 차감 또는 별도 회수

6. 데이터 기준

  • 스크래핑 기준 시각: 매일 오전 10시
  • 지급 시각: 다음날 오전 11시 30분과 오후 6시 (하루 2회, 주말·공휴일 포함 매일)
  • 지급 횟수: 가맹점 1개 기준 하루 2회 (오전 11:30 이후 매입·확인분은 오후 6시 추가 선정산으로 반영)
  • 선정산 기준: 전일 승인 또는 매입 데이터
  • 매출 상세 기준일: 매입일 기준으로 검토 중
  • 화면에는 최종 업데이트 일시를 표시하는 방향
03

용어·상태값

6대 개념 분리 원칙과 내부/노출 용어 매핑.

1. 기본 용어

선정산

플랫폼 또는 카드사로부터 실제 정산금이 입금되기 전에 PayHug가 가맹점에 먼저 지급하는 금액.

승인 매출

카드 또는 배달 플랫폼에서 결제가 승인된 매출.

매입 매출

승인된 거래 중 카드사 또는 플랫폼 정산 대상으로 확정된 매출.

반영 매출액

현재 선정산 계산에 포함된 매출의 합계.

선정산 반영 금액

전체 매출 중 실제 선정산 계산에 포함된 금액.

예상 지급액

아직 최종 확정되지 않은 데이터를 기준으로 계산한 지급 예정 금액.

확정 지급액

수수료·환급·차감·제외·회수 등을 모두 반영한 최종 지급 금액.

예상 지급 차액

정확한 정의는 미확정.

후보:

  • 최초 예상 지급액과 최종 지급액의 차이
  • 당사 계산액과 플랫폼 최종 입금액의 차이
  • 추가 지급 또는 회수 예정 금액
  • 대사 불일치 금액

정규 매니저와 정의 확정 필요.

2. 지급 관련 용어

미지급금

원래 가맹점에게 지급해야 했으나 실제 지급되지 않은 금액.

예:

  • 플랫폼 환급 누락
  • 지급 배치 누락
  • 계좌 오류
  • 바로이체 실패
  • 데이터 지연으로 인한 지급 누락

선정산 제외금액

정책상 이번 선정산 지급 대상에서 제외한 금액.

예:

  • 매입 미확정
  • 검증 불가
  • 위험 거래
  • 지급 보류
  • 한도 초과
  • 계약상 제외

미지급금과 선정산 제외금액은 구분해야 한다.

바로이체 대상금액

정규 선정산 지급과 별도로 지급해야 하는 금액으로 추정된다.

정확한 생성 조건은 확인 필요.

바로이체 미지급

바로이체 대상으로 생성되었으나 아직 실제 지급되지 않은 금액 또는 상태로 추정된다.

3. 환급 관련 용어

플랫폼 환급

플랫폼이 가맹점에게 돌려주도록 정산 상세에 반영한 금액.

금액 방향:

  • 원칙적으로 +
  • 가맹점에게 추가 지급

자체환급분

현재 운영에서 사용하는 표현.

당사가 자체 보상하는 금액이라기보다, 플랫폼이 자체적으로 생성한 환급 항목을 의미하는 것으로 파악됨.

가맹점 노출 용어는 플랫폼 환급금 권장.

4. 회수 관련 용어

과지급

PayHug가 가맹점에게 실제 지급해야 할 금액보다 더 지급한 발생 금액.

미회수금

과지급 또는 기타 회수 사유가 발생한 뒤 아직 회수되지 않은 잔액.

권장 구분:

  • 과지급: 발생 원인과 최초 금액
  • 미회수금: 현재 남아 있는 회수 잔액

회수

가맹점에게 초과 지급된 금액을 다시 확보하는 처리.

가능 방식:

  • 다음 선정산액에서 차감
  • 락계좌에서 회수
  • 가맹점 직접 입금
  • 운영자 수동 처리
  • 부분 회수
  • 분할 회수

상계

가맹점에게 새로 지급할 금액과 회수할 금액을 서로 차감하여 정산하는 방식.

정산 로직

미리 받는 돈이 어떻게 계산되고 지급되는지.

1. 기본 산식

기본 구조:

전일 매출
- 카드 수수료
- 배달 플랫폼 수수료
- PayHug 채권매입수수료
- 이체수수료
+ 플랫폼 환급
+ 추가 지급
- 선정산 제외금액
- 이전 과지급 회수금

2. 카드 선정산 산식

기존 협의에서 파악된 산식:

최종 선정산금액

× (1 - PayHug 수수료율)
- 이체수수료 300원

예외 케이스

플랫폼별 예외와 음수·조정 처리.

1. 배달의민족 우리가게클릭비

정상 케이스

  • 우리가게클릭비는 광고비
  • 플랫폼 정산에서 -
  • 선정산 지급액에서 차감

예외 케이스

우리가게클릭비 특별프로모션 환급이 동일 항목 안에 포함됨.

  • 일반 광고비: -
  • 특별프로모션 환급: +
  • 환급액이 차감액보다 크면 최종 순액이 +가 될 수 있음
  • 기존 시스템은 우리가게클릭비를 무조건 차감 처리
  • 지급해야 할 금액까지 회수하여 과회수 발생
  • 이후 정정하여 재지급

개발 필요사항

  • 동일 품목이라도 금액 부호에 따라 지급·차감 분기
  • 가능하면 일반 광고비와 프로모션 환급 세부 항목 분리
  • 합산 순액 기준인지 세부 항목 기준인지 정책 확정
  • 이미 차감한 후 환급이 확인되면 추가 지급 처리

2. 가게배달 정산금

정상 케이스

  • 기존에는 항상 +
  • 선정산 지급액에 포함

예외 케이스

  • - 금액 발생
